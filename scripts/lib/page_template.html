Minimum-area convex lattice polygons

What is the smallest area of a convex polygon with n vertices, all at integer points? We computed the exact answer for every n up to {{LAST}}, and very likely answers up to n = 1000.

The doubled minimum area is OEIS A070911; the minimum number of interior lattice points, (A070911(n) − n + 2)/2, is A063984. Before this work the values were known for n ≤ 150.

How the values were computed

Certified values. A dynamic program over convex lattice chains, organized by lattice width, keeps for each chain end the best trade-offs between direction and area, extends chains only through triangles without interior lattice points, and fills its table in order of the number of chain vertices. A lower bound on the area in terms of the lattice width tells it when to stop. Every optimal polygon is reconstructed and checked independently. Certifying all n ≤ 511 took about 10 hours on a desktop computer.

Conjectured values. A much faster heuristic finds the best polygon whose edge vectors all lie in a small square of half-side ⌈√(2n/3)⌉. Each value is the area of an explicit polygon, so it is a proven upper bound. Where the true minimum is known (n ≤ 511), the heuristic was optimal for 484 of 509 values, including every n ≥ 296, and never more than 0.121% too large. We expect most values beyond n = {{LAST}} to be optimal, but they are not proven.

Reproduce

The programs (Rust) and scripts (Ruby) are in the repository:

scripts/build                                 # build the programs
scripts/certified 300 --spill /big/disk/spill  # certified values, 3 ≤ n ≤ 300
scripts/conjectured 512 1000                  # heuristic values, 512 ≤ n ≤ 1000

The reproduction guide lists the hardware we used, how to compile, and the time, memory and disk each run needs.
